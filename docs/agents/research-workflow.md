# 研究工作流程

本流程用于从库内问题形成可核验回答，并在用户确认后保存。资料不足时说明缺口；公开来源补充属于后续任务，不在本流程中自动联网。

## 查找与核验

1. 阅读 `wiki/索引.md` 获取入口，同时用 `rg --files wiki raw` 列出文件，并用 `rg -n -i "关键词" wiki raw` 全文查找；索引不是完整清单。
2. 阅读相关知识页和原始资料。摘要与 Wiki 结论只能帮助定位，重要事实、数字和引语必须回到可读原文核对。
3. 回答具体问题，给关键判断附短摘录和原文位置。区分原文事实、来源观点、综合推断及待核验内容，不把推断写成事实。
4. 文本资料标注相对路径和章节、段落或行号。PDF 分开写印刷页码和阅读器页序；网页保留原始 URL、标题、日期和章节或段落。无法确定的位置明确说明，不猜位置。
5. 读取既有页面时兼容 frontmatter 的 `source` 和 `sources`。新建或更新页面按 `SCHEMA.md` 使用 `source` 字段；不要为本流程批量改写旧页面。
6. 仅凭摘要、无法读取原文或证据冲突时，明确标出限制；不要提升结论置信度或自动写入 `confidence: VERIFIED`。

## 保存与复用

1. 判断最合适的已有页面并优先更新；没有合适页面时才新建。按 `SCHEMA.md` 保留页面类别和字段。
2. 生成一份 JSON 计划，包含完整的目标页面内容、完整索引内容和一条新日志记录。例如：

```json
{
  "scope": "最终研究问题及其范围约束",
  "page": {
    "path": "wiki/topics/页面标题.md",
    "content": "目标页面的完整内容"
  },
  "index": "更新后的 wiki/索引.md 完整内容",
  "log_entry": "## [YYYY-MM-DD] 研究 | 页面标题\n\n- 本次修改及依据"
}
```

3. 运行 `python scripts/wiki-save.py preview <计划文件.json>`，逐项检查页面、索引和日志的实际差异。该命令只保存活动预览，不改动知识库文件。
4. 把差异和指纹展示给用户，并等待用户明确确认。范围或目标页面变化时重新生成预览；新预览会使旧指纹失效。目标页面、索引或日志在预览后变化时，工具拒绝写入。
5. `preview` 可跨平台使用；确认保存目前只支持 Windows。用户确认后运行 `python scripts/wiki-save.py confirm <指纹>`。工具先以系统共享模式锁住三个目标，拒绝与已有写入或替换冲突的保存，再于锁内复核指纹并通过锁定句柄写入；发现目标已有多个硬链接时拒绝保存。该锁阻止常规编辑写入和替换，但不阻止外部在确认期间创建新硬链接，流程不保证抵御这种主动改变链接拓扑的操作。确认后重复运行同一指纹不会重复写入。
6. 保存后读取实际页面、索引与日志，再用全文搜索确认结果可查。向用户报告真实路径和变更；不自动提交、推送或发布。

保存计划只写入知识页面、`wiki/索引.md` 和 `wiki/日志.md`。原始资料只读，日志只能追加。用户未确认时不得运行 `confirm`。

写入前会将三个目标的原内容和计划内容持久化到 `.scratch/research-workbench/ticket8-save-recovery.json`，成功或已回滚后才清理。若进程中断、回滚失败或下次确认报告存在恢复副本，先运行 `python scripts/wiki-save.py recover`；恢复命令只处理完整匹配预览前或预览后内容的目标。此前不存在的新页面仅在完整匹配预览后内容时删除。遇到部分写入或未知内容时，会停止并保留副本供人工核验，不会覆盖它们。`confirm` 在恢复副本存在时拒绝写入。
